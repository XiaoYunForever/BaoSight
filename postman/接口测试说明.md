# Postman 接口与报告测试

## 启动后端

### 方式一：Maven 自动下载并启动 Tomcat（推荐）

刷新 IDEA 右侧 Maven 项目后，插件列表中会出现 `cargo`，使用的是 Tomcat 9。
在 Maven 的“执行 Maven 目标”中输入 `-DskipTests package cargo:run`，或在项目终端运行：

```powershell
mvn -DskipTests package cargo:run
```

首次启动需要下载 Cargo 和 Tomcat。`package` 先生成最新 WAR，`cargo:run` 再部署并保持服务运行；不要只运行 cargo:run 而漏掉打包。这里跳过 JUnit，业务用例由 Postman 请求触发。
默认接口地址是 `http://localhost:8080/BaoSight/index/test`。终端按 Ctrl+C 停止；IDEA 中停止对应 Maven 运行任务。

如果 8080 被占用，可运行 `mvn -DskipTests -Dcargo.servlet.port=8081 package cargo:run`，并同步修改 Postman 的 baseUrl。

参考：https://codehaus-cargo.github.io/cargo/Maven+3+Plugin+Getting+Started.html

### 方式二：使用外部 Tomcat

本项目是 Spring MVC WAR 项目，不是 Spring Boot；JUnit 测试不会启动 HTTP 服务。

1. 在 IDEA 使用本机 Tomcat 9 创建 Local 运行配置（项目使用 javax.servlet，不能直接用 Tomcat 10/11）。
2. Deployment 添加本项目的 WAR exploded，Application context 设置为 `/BaoSight`。
3. 确认部署资源包含 `web/WEB-INF/web.xml`、编译后的 `WEB-INF/classes` 和 Maven 依赖。
4. 启动 Tomcat，假设 HTTP 端口为 8080，请求地址为 `http://localhost:8080/BaoSight/index/test`。

也可以先运行 `mvn -DskipTests package`，再将 `target/BaoSight.war` 放入 Tomcat 的 webapps 目录并启动 Tomcat。第一次构建需要下载依赖和插件。`-DskipTests` 避免打包时启动现有浏览器集成测试。

## Postman 请求

导入本目录下 `BaoSight.postman_collection.json`，按实际 Tomcat 端口和 context 修改集合变量 `baseUrl`。
请求为 POST，Body 选择 raw / JSON，Content-Type 为 application/json：

```json
{
  "codelist": ["601"],
  "mode": "SIMULATION",
  "device": {
    "manufacturer": "测试厂商",
    "model": "测试型号",
    "version": "1.0"
  }
}
```

执行模式必须与 Java 枚举名称一致。当前只实现了 601；REAL_DEVICE 当前使用 UaClient 中的固定远程地址，本次请使用 SIMULATION。

这是同步请求：点击 Send 后等待整个用例和评分完成，才返回报告。Postman 的 Request timeout in ms 可设为 0（不限制），或设为足够长的时间，例如 300000。

## 当前执行范围与预期

请求进入 controller → mainRun → case_opcua_01 → evalu_opcua_01 → evaluationAll → JSON 报告。
601 内的浏览器建项目、下载步骤仍保持注释；公共执行入口仍会启动浏览器并打开 application.properties 中的 plc.ide.url，因此本机浏览器及 PLC IDE 页面仍应可用。

当前测试账号 admin1 的客户端密码是 admin1234，而仿真服务器密码是 admin123。保持该测试配置时，正常预期是连接失败后继续评分，返回 HTTP 200、总分 0、OPC UA 权重 100、用例 601 得分 0/20，以及 errorText 扣分说明。这是业务测试失败报告，不是 HTTP 接口失败。

如需成功场景，把执行用例 ConnectConfig 中的密码改为 admin123，重新部署后再请求；用户名密码目前不是请求 DTO 字段，不能通过 Postman 传入。

报告入口：finalScore；protocolResults.opcua.percentage；protocolResults.opcua.caseResults 中的 caseCode / score / maxScore / errorText。

出现 404 时检查端口、context 和部署日志；400 时检查 JSON 和枚举；500 时查看 Tomcat 异常日志，浏览器启动等执行异常不会生成完整报告。每次测试结束后，keepOpen=true 会保留浏览器，需自行关闭；本次未修改该偏好。

此次未自动部署 Tomcat 或实际执行浏览器/PLC 联调，请在本机启动 Tomcat 后用集合验证。
